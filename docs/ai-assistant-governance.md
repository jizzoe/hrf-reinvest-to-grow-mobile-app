# AI Assistant Governance

## Data And Safety

Only synthetic HTG prototype data is permitted. Never commit or expose
credentials, access tokens, OAuth material, EAS signing material, device
identifiers, participant data, production financial data, screenshots with such
data, or mutable approval records. AI output proposes work; it cannot finalize a
financial record, approve financing, or manufacture impact claims.

## Approval Model

Interactive delivery is the default. A bounded autonomous run must name its
target, repository/branch, permitted local and external mutations, expiration,
validation evidence, correction budget, and stopping condition. It pauses for
material product/architecture decisions, authentication, external writes not
explicitly approved, cost commitments, sensitive data, destructive actions, or
scope expansion.

## M1 Phase-1 Boundary

The profile is `prototype-rapid`: deterministic component checks and evidence
are mandatory, while isolated independent review is not. The allowed component
outcome is manual offline sale/expense capture with confirmation, SQLite
durability, local activity/totals, localization, and sync-shaped local outbox
records. EAS Android signing/build work is constrained to the approved free-plan
internal-distribution APK route. AWS, other cloud providers, live APIs, iOS,
speech, and receipt/OCR require separately approved changes.

## GitHub And EAS

Repository-local GitHub lifecycle configuration is non-secret and lives in
`config/sdd-github.json`. Issue/Project/PR changes are external writes requiring
current authorization even when a reusable skill is available. EAS project/build
actions likewise require the approved task and current authorization. Never save
credentials or project-field/item IDs in repository files.
